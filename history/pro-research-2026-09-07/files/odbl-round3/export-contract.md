# Geographic export contract, version br-geography-export-1
Proposed implementation specification dated 2026-09-07. Source keys resolve in sources.yaml. This pack contains no actual climb export, deployed page, live asset admission or production-system audit.
## Authoritative unit and completeness
Export the published geographic database, including all geographic fields and public revisions used by current or retained historical outputs. Canon identity, geometry, source-derived attributes, accepted corrections and public policy facts belong here. Do not omit a geographic field merely because it is absent from this initial field list; schema changes require a classification and export-completeness test.
Exclude the private candidate atlas, independent rider observations/economic rows, private evidence and operational secrets. Exclusion is an architectural boundary, not permission to hide geographic contents actually incorporated into the public derivative.
Each climb revision contains canon_id, canon_version, geographic_revision_id, predecessor references, actual continuity policy, public/retired status, ratification/publication timestamps and the release memberships. Current records and historical records are distinguishable.
Centerline: full ordered authoritative geometry, ascending direction, coordinate/CRS specification, stored precision, horizontal length and the exact source geometry representation. GeoJSON is the convenience rendering; binary EWKB or an equivalent lossless source representation preserves the stored geometry when conversion/reformatting would otherwise alter it.
Gates: exact start/finish LineStrings, endpoints, anchor/center/orientation where stored, half-extents, actual applied overrides and public revision rationale. Never rebuild a timing gate from rounded center coordinates or an H3 cell.
Corridor: export the actual stored metric PostGIS geography-buffer result as Polygon/MultiPolygon, not the compiler preview; include the applied width and geometry-policy reference. H3 cells are sorted unique hexadecimal strings with resolution and coverage-policy/version, not JavaScript numeric IDs or a substitute for the authoritative corridor.
Profile samples: exact stored station distances and elevations, units/datum, sampling/interpolation policy, first and final endpoint samples, and all known per-sample source contributions. Preserve missing values as null plus an explicit reason; no unknown-to-zero conversion. Do not silently add or alter samples on an already registered profile.
For new releases, follow the ratified sampling policy. The proposed exact-10 m-plus-endpoint amendment is not silently applied to older stored profiles. A 10 m station interval is not a claim of 10 m source accuracy.
Include ordered OSM way references, source snapshot/extract date and digest, public asset identifiers/editions, input byte checksums, supplied source notices, public processing parameters, transformations, manual accepted corrections and public policy-version facts. Omit private paths, credentials and personal evidence identifiers.
Export the exact canonical profile bytes used by the existing hash serializer, its identifier/specification and at least one known-good test vector. Include the actual v1 commitment bytes where present. A pretty-printed JSON re-encoding is not the authoritative hash input.
The attached documents do not supply that serializer’s implemented byte-level specification. Bind to the existing implementation and extract its test vector; do not invent a replacement serializer in this licensing change.
Proposed v2 course_root/registration_root fields remain absent or explicitly not_applicable until separately ratified and implemented. The export may have an independent full-payload checksum without asserting that v1 commits to those additional fields.
Current v1 commitment layout is 0x01, UUID bytes, u16 big-endian canon version, 13 zero reserved bytes, and 32-byte BLAKE3 of canonical profile bytes [canon-build-decisions.txt D12].
The actual corridor authority is the stored metric geography buffer, not compiler corridor_wkt [canon-build-decisions.txt frozen arithmetic, corridor].
The atlas digest describes v2 as a proposed amendment, and proposes complete per-sample source receipts [atlas-round2-digest.txt identity and manifest sections].
Legacy provenance must be honestly marked incomplete where not available; do not manufacture per-sample receipts. Reconstruct provenance from archived assets where possible, and block new use of an unresolved restricted source. Do not remove old public geographic bytes merely because their provenance record is being repaired.
## Four independent version coordinates
canon_id is stable identity. canon_version retains its protocol meaning, including boundary/record-continuity rules. geographic_revision_id is the immutable content identity of the geographic payload for that canon version. release_id is the immutable published collection/manifest. export_schema_version versions the transport contract separately.
A permitted profile/tolerance/metadata correction can require a new geographic revision and release without inventing a new sporting rule or erasing a prior commitment. New geometric bytes never overwrite an archived revision. A canon-version increment is governed by the protocol, not by ZIP creation.
Use a content-addressed release manifest: ordered revision keys and per-file byte hashes form the hashed payload; exclude the manifest’s own digest and detached signature from their own input. Store an exact byte manifest and detached digest/signature. The mutable latest pointer resolves once to an immutable release ID per operation.
Preserve every release and exact committed profile still referenced by historical public outputs. A newer compiler or DEM cannot silently replace registered bytes. Registration is permitted only after its exact geographic snapshot and complete data offer are available.
## Files and format
Serve /open-data as the stable landing page and /open-data/releases/{release_id}/ as the immutable release path. These are proposed paths, not asserted live URLs. Serve one complete ZIP and its individual members without account or wallet authentication.
manifest.json: schema/release IDs, publication timestamp, included regions/revisions, counts, actual byte lengths, per-file checksums, source/notice-set hashes, and excluded independent-data scope.
climbs.jsonl: one complete climb revision per line, using JSON-compatible fields and GeoJSON geometry members. No map simplification in authoritative geometry. Include public technical metadata needed to interpret values.
profiles.jsonl: ordered samples keyed by full revision identity, with datum, source contribution IDs and missing-state information. source_contributions can normalize repeated sample provenance while preserving all interpolation/blending inputs.
SOURCES.jsonl: public asset/licence records and source-update dates. Do not dump the private admission-review database. NOTICES.txt: the exact resolved union of notices for included source contents, not a list of every potential regional fallback.
canonical-bytes/{geographic_revision_id}/: exact profile bytes and, where needed, lossless stored geometry. schemas/: machine-readable export schemas and byte-encoding specification. licences/: applicable legal texts or their identified URIs, with preserved notices. checksum file excludes its own entry and the containing ZIP’s hash is provided alongside the ZIP.
UTF-8; WGS84 GeoJSON coordinate order longitude, latitude; explicit distance/elevation units; per-profile vertical datum; integers/enumerated states where appropriate; stable station ordering; no binary floats for H3 identifiers. Retain a lossless original when convenience serialization changes representation.
Optional GeoPackage, region subsets and change-only diffs can supplement the full snapshot; none replaces the complete source offer. A global release index must enumerate every shard if scale makes one ZIP impractical.
## Size budget, not a measurement
For illustration, 57 climbs averaging 1 km at exact 10 m spacing would yield 5,757 samples including endpoints. Depending on corridor vertices, source receipts and history, reserve roughly 3–20 MiB uncompressed and 1–8 MiB compressed for a small current release; these are planning assumptions, not observed sizes or ceilings.
A useful growth model is total profile receipt bytes + centerline/gate/corridor vertex bytes + H3 bytes + shared source/notices + retained-history bytes. At an assumed 100 KB per revision, 10,000 revisions are about 1 GB decimal before compression. Measure the real build and show exact byte counts; never truncate geometry to meet a size estimate.
## Link contract
Portal climb page: adjacent visible Data and sources link tied to the displayed revision. Portal footer: Open climb data. Explorer: persistent map/source control and revision-specific data-offer link on each climb/registration page.
API geographic responses: additive metadata with exact release/revision identity, licence URL, attribution, notice IDs, source-offer URL and immutable manifest URL. Preserve existing matched-climbs response compatibility; use an agreed additive extension, or transitional Link headers plus documented metadata endpoint if the wire shape cannot accept it.
Share-card image: embedded credits, written OSM copyright URL and short durable data/source URL or resolver. Docs: Open data page links complete release, schema, source notices and archive; embedded maps/profile images retain their own credit. A docs-only link does not satisfy every detached output.
## Publication test
Fetch the complete ZIP anonymously; verify hashes; rebuild the public geographic read model from it; compare every exported geographic field and exact profile hash against the frozen production release. Ensure missing geographic fields, unresolved notices, stale version links and omitted historical public revisions fail the build.
Compare all actual geographic API fields with an explicit schema classification map: exported/public-derived, independent observation, independent economics, or operational/private. An unclassified new field fails CI.
Basis for machine-readable offer and preserving notices is ODbL §§4.2 and 4.6 [S1]; the unauthenticated policy also implements protocol-truths.txt §14.7.
