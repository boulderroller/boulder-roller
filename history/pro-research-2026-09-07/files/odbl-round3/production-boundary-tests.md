# Published-registry boundary: production acceptance tests
These are integration requirements, not a claim that the live repository has passed them. boundary_contract.py and its tests demonstrate a small immutable-reader/noninterference contract only; they do not implement the geometry matcher, protocol hashing, Postgres permissions, frontend rendering or chain submission.
Geography dependency rule: a production map overlay, matcher, geographic API, export, share renderer or registration builder consumes only an immutable published geographic release. Independently admitted CARTO/terrain display layers are separate permitted inputs, not candidate-atlas access. Matching may read authorized private ride evidence; economic operations may read their own records.
Private data can enter public geography only through an explicit promotion transaction that freezes the selected geographic bytes, clears source rights and ratification, builds/verifies the complete export, publishes it, then exposes the release to production. A publication status boolean on a query over the private atlas is not this boundary.
Database roles: atlas compiler/reviewer can read private candidates; dedicated publisher can create approved public snapshots. Web/API/renderer/registration geographic readers have no private-atlas schema/table/view/function/storage credentials or grants. They are not owners, superusers or BYPASSRLS/service-role equivalents with broad reach. Audit security-definer functions, views, shared caches and object-store paths as well as tables.
MATCH-01: fix an immutable release, rider recording, external display tiles, public/economic inputs and clock. Add a private candidate that is an exact better match, rename private candidates, change their count/ranking, move their gates, and alter private DEMs. Every public response, map layer, profile, share payload and unsigned registration payload must remain identical after explicitly listed nondeterministic transport fields are normalized.
MATCH-02: give the ride only a private candidate match and no public match. Return no published-climb match. Do not emit private candidate IDs, geometry, titles, elevations, counts, nomination rankings or private existence hints.
READ-01: execute direct SELECTs and accesses through every reachable view/function under the actual deployed API, matcher, renderer and registration identities; access to atlas_private and its storage objects must fail. A static import check alone does not pass this test.
READ-02: instrument database/object-store/network access for every public route and queued job. Fail on private-atlas reads even when the result is filtered away, hashed, cached or omitted from the final response. Ensure no credentials permit a fallback read path.
READ-03: a missing public revision returns the endpoint’s explicit not-found/unavailable state. No atlas fallback, compiler-on-demand, candidate count, private search suggestion or zero-valued counterfeit geography is permitted.
CACHE-01: warm caches from a reviewer session and replay public requests. Candidate results must not be visible through shared Redis keys, CDN URLs, signed URLs, SSR payloads, observability endpoints or queue payloads. Public caches are namespaced by immutable release and revision.
PUBLISH-01: mutate a candidate after approval; publication must either retain the already frozen approved bytes or reject the mismatch. Never export one geometry while registering/matching another.
PUBLISH-02: race the latest pointer during map, matching and registration operations. Each operation uses exactly one resolved immutable release; no mixed-release profile/gates/corridor. History remains retrievable and an archive outage does not trigger a private fallback.
PUBLISH-03: fail admission for one contributing DEM or remove a required notice. New release activation and registration fail. Previously published bytes are not silently replaced or removed; an incident is handled explicitly.
EXPORT-01: anonymously fetch the full release; verify byte hashes and complete geographic-field coverage; rebuild the public geographic model and compare to the deployed immutable snapshot. Verify exact existing BLAKE3 profile test vectors without inventing a new serializer.
REGISTER-01: registration builder requires a published revision and a resolvable full data offer. Check current v1 bytes against the source D12 layout and the real canonical serializer. Reject an absent/changed public revision. No v2 semantics are introduced by this test pack.
PUBLIC-01: enumerate public map, list, nearest/search, profile, share, API, explorer and registration surfaces. Every geographic output refers to a revision in the public release manifest. Validate notice-source union for basemap, terrain and profile independently; a private candidate commitment is not allowed as a harmless diagnostic.
INVARIANT: for fixed public release P and authorized independent inputs I and display inputs E, public_output(P,I,E,C1) = public_output(P,I,E,C2) for any two private-atlas states C1 and C2. Noninterference is stronger than testing only that a marker string is absent.
LIMIT: finite regression tests do not prove all future paths. The enforceable capability boundary plus exhaustive current-surface tests is the target. Include route/consumer enumeration and permission audit in release CI; a newly added consumer fails until classified.
